## Unreleased (2026-11-01, overlay status probe deadline and shared peer addresses, #1565)

- Every provider status command (`netbird status --json`, `tailscale status --json`) runs under one deadline, `status_timeout_secs` in `overlays.toml` (default 10, `1..=120`). A command still running at the deadline is killed and reaped with any process it started and the probe fails as `<overlay>_state_unavailable`, so a wedged overlay daemon no longer hangs host listing, discovery, `--host` resolution or the daemon's listener retry.
- A peer address that the status lists for another peer or for this machine (for Tailscale, any address of a node) is not used for routing. Selecting those peers or the address is `overlay_host_ambiguous` naming every peer that lists it, and `host list` / `host discover` show them as `candidate` records without an address and with `reason = "address_ambiguous"`.
