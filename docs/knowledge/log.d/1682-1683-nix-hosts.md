## Unreleased (2026-10-30, Nix hosts: installer and stale search path, #1682 #1683)

- `packaging/verify-archive`, and so `packaging/install-daemon.sh`, finds `id` in `/usr/bin`, `/bin` or `/run/current-system/sw/bin` (the NixOS system profile) instead of the fixed `/usr/bin/id`, and still never takes it from `PATH`. A directory counts only when it is closed to group and others and owned by root or by the user. A host with none of them is refused with `no trusted id found` and nothing changed.
- On macOS, a `service_upgrade_sessions_at_risk` refusal now carries a warning when the search path the upgrade judged with (recorded in `service.toml`) lists entries that a fresh install would not record (a Nix profile path pinned to an older generation): it names both sets and points to re-recording the path (`pohunek service uninstall`, reinstall the installed version, rerun the upgrade) instead of `--accept-runtime-loss`. The recorded path is still the validated canonical path; see the update runbook.
