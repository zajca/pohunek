## Unreleased (2026-11-01, Stop repeats the identity report and SessionStart traces its run, #1194)

- The Claude state hook's `stop` action sends `identity_report` before its `subagent_snapshot` when the Stop input names a `session_id` (with its `transcript_path`); the report goes to the worker only, is ordered by `sequence`, and does not depend on the task list (an unusable list still sends the identity). `Stop` was chosen as the only carrier because `UserPromptSubmit` drains its input undecoded on purpose. The `session` action writes `hook_started` as soon as the interpreter runs its script and `hook_finished` at its normal exit. The shell part writes no trace line (a POSIX shell cannot open the trace without following a symlink), so a hook killed during the interpreter's own start, the Xcode-shim case of #1192, still leaves nothing; the pinned interpreter that would remove that cause is #1810. `EXPECTED_INTEGRATION_VERSION` and `POHUNEK_INTEGRATION_VERSION` go 15 -> 16 for every managed asset (the version marker is shared), so existing installs heal only after a reinstall. The Stop payload's `session_id` and `transcript_path` are Claude's common hook input fields as for `UserPromptSubmit`; the recorded Stop sequences are sanitized and do not show them, so a live Claude Stop was not re-recorded here. Scenarios: the scripted-worker claims of a Stop with a session id, with an unusable task list and without a session id, and the start/finish/killed trace lines of a SessionStart run; the real-worker harness does not journal a native reference without a daemon that verifies the launch, so recovery is pinned at the claim the worker receives.
