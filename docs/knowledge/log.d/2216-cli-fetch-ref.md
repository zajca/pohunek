## Unreleased (2026-11-12, session new fetch_ref CLI, #2216)

- `pohunek session new --fetch-ref <ref> --fetch-commit <sha>` (requires `--branch`) fetches one extra ref from `origin` into the worktree's repository without checking it out (a GitHub pull-request head is `refs/pull/<n>/head`); the commit is a full lowercase hex id the ref must peel to, the `--json` output carries it as `fetched_ref` and the human output prints `fetched: <source> -> <ref> at <commit>`. A host whose daemon does not advertise `session_new_fetch_ref_supported` is refused with `session_new_fetch_ref_unsupported` before the session is created; a first response without the outcome from an advertised daemon fails with `fetch_ref_outcome_missing` (needs git 2.29 or newer on the host). `pohunek assistant` takes no such flag. See the CLI reference and [Worktrees](concepts/worktrees.md#fetching-one-extra-ref).
