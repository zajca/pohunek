## Unreleased (2026-10-22, session record writers keep metadata edits, #1484)

Every unconditional write of a session record, including the relaunch of a resume and the supervision retry that classifies a runtime, takes the lock a `session.set_metadata` edit holds and carries the metadata of the session's registered entry into the record and the entry it installs. A metadata edit acknowledged while such a write is in flight is therefore no longer lost to an older snapshot of the record. The upgrade hint of `pohunek session policy set --idle-stop-after` names a release that includes the default, without a number, when the connected daemon's version is not older than the CLI's. See `docs/cli.md`.
