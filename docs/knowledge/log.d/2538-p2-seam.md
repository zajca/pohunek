## Unreleased (2026-11-27, libghostty-vt screen-model seam, #2538)

- `pohunek-terminal`'s `TerminalTracker` now runs one of two screen backends:
  vt100 (the default in this slice) or libghostty-vt, selected per build with
  the `libghostty` cargo feature and per tracker with
  `TerminalTracker::with_model(ModelKind, ..)`. The FFI moved from the spike
  into the new `crates/terminal-ghostty-sys` crate, the only crate that may use
  `unsafe`; `pohunek-terminal` keeps `#![forbid(unsafe_code)]`. OSC title,
  progress and OSC 7501 probes stay byte-driven and shared between the models,
  so the worker protocol's snapshot and probe contract does not depend on the
  screen model. No CLI, protocol or config change: the feature is off by
  default and no shipped binary links the library yet.
- Source map: `crates/terminal-ghostty-sys/src/lib.rs` added.
- `TerminalSnapshot::visible_text` (and therefore `session.screen`'s
  `visible_lines`) now means the active screen rows only, on both backends:
  the libghostty backend reads them cell by cell through the sys crate's
  `HeadlessTerminal::visible_text`, so the scrollback the library retains can
  no longer grow a snapshot past the screen (the `format_plain` history view
  stays available to the spike only). Stated for embedders in
  `docs/public-api.md` under `session.screen`.
