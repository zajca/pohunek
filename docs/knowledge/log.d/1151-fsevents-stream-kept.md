## Unreleased (2026-11-01, FSEvents stream kept across passes, #1151)

- `Watcher::reconcile` no longer calls `unregister_all()` unconditionally: it calls the new `WatchBackend::retain_roots(roots)`, whose default is `unregister_all()` (inotify keeps its per-pass rewalk) and which `FsEventsBackend` overrides to `unwatch` only the registered roots that left the set. `register_root` already returned early for an unchanged root, and now also forgets a root that vanished so a root created again starts a fresh stream; a canonical-path change re-watches that root only. `notify` 8.2.0 stops and recreates the whole stream on every `watch`/`unwatch`, so the window in which a change was not delivered live no longer recurs every pass. Scenarios: five on the `WatchBackend` boundary in `external/watch/tests.rs` (unchanged set, rescan and tree change, added root, removed root, default rebuild; they fail when `reconcile` goes back to `unregister_all()`), two `FsEventsBackend` tests, and the live test `a_transcript_written_right_after_a_pass_is_indexed_by_a_live_event` on both backends. On zajcaair (macOS 15, FSEvents) the live test passes with and without the fix: the window after a stream start is too short on real hardware to observe from a test, so the stream-keeping guarantee is pinned at the backend boundary and the live test is a regression guard for the acceptance behaviour. The live tests keep their 30 s bound for waits after a pass, which the inotify rewalk still needs.
