`pohunek plugin profile create <name> --base <runtime> [--home <abs-path>] [--arg <a>]... [--secret-env <NAME>]... [--replace <digest>] [--dry-run] [--json]` creates a host agent profile through the new local-only `package.create_profile` method instead of a hand-written file. The daemon composes and validates the profile, pins a package-served base to the selected package, and writes it atomically at mode 0600; `[env]` holds only the runtime's config home variable, taken from the package descriptor. A credential-shaped argument or home, a relative or `~` home, a symlinked agents directory and an existing name without `--replace <file digest>` are refused with `package_profile_credential_literal`, `package_profile_home_invalid`, `package_profile_dir_unsafe` and `package_profile_exists` / `package_profile_digest_mismatch`. `plugin profile list` reports a `file_digest` per profile, and `host.inspect` reports `package_create_profile_supported`. ([#2132](https://github.com/zajca/pohunek/issues/2132))
