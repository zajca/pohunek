The default screen model is now libghostty-vt: every default build renders `session.screen` results and attach repaints with the libghostty backend (`default = ["libghostty"]` in `crates/terminal`, forwarded by the CLI, daemon, session worker and xtask; the CI and release lanes provide the pinned library through the `libghostty-vt` action). The vt100 product remains as the `--no-default-features` fallback build — no Zig toolchain, no C library — and reports `screen_model: "vt100"`; the fallback CLI keeps the embedded agent skill (`--no-default-features --features embed-agent-skill`; the skill is not tied to the screen model) and the kit has a vt100 daemon variant (`--no-default-features --features daemon`). No protocol version bump was needed: `screen_model`/`format_version` stay optional on the wire, so older workers, daemons and clients keep working unchanged. Rollback is six manifest lines, not one: drop `"libghostty"` from `default` in `crates/terminal/Cargo.toml` and in `crates/cli`, `crates/daemon`, `crates/session-worker`, `crates/xtask` and `crates/plugin-kit` (the consumers forward the feature in their own defaults — the kit through its own `libghostty` feature — so flipping the library crate alone does not roll the product back). ([#2538](https://github.com/zajca/pohunek/issues/2538))
