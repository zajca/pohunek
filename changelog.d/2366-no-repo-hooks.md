`pohunek session new --no-repo-hooks` (and `skip_repo_hooks` on `session.new`, behind the new `session_new_skip_repo_hooks_supported` capability) starts a session that runs none of the checkout's own hooks, neither `.pohunek/hooks/<event>` nor the legacy `.pohunek/setup`, for any lifecycle event and for its whole life, including a resume, a daemon restart and a failed create's rollback; the host's hook scripts still run. The session also runs none of git's own hooks, which a relative `core.hooksPath` (husky style) would resolve inside the checkout: the daemon's git commands for it run with `core.hooksPath=/dev/null`, and the agent and the host hook scripts get that setting as one more `GIT_CONFIG_COUNT` pair behind the pairs their environment already has (an agent environment with `GIT_CONFIG_PARAMETERS` or a non-numeric `GIT_CONFIG_COUNT` fails the start with `git_hooks_env_conflict`). Sessions started later in the same checkout do not inherit the switch. Use it for a checkout whose content you do not trust, such as a pull-request head. The session reports `skip_repo_hooks: true`, a `[hooks] required` event the host has no script for fails the start with `hook_required_skipped` before anything runs, and the Rust client and the TypeScript SDK refuse the switch with `session_new_skip_repo_hooks_unsupported` on a daemon that predates it. `host inspect --json` reports `host_hooks`: which events have a host-global hook script, without paths. The store moves to schema 21. ([#2366](https://github.com/zajca/pohunek/issues/2366))
