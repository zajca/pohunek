CI: the macOS jobs of `ci.yml` (`platform contracts (arm64)`, `macOS release daemon build (macos-15)`, `macOS package install and upgrade (macos-15)`, `pinned Hermes compatibility (macOS arm64, model-free)` and `SDK workspace (macOS arm64)`) now run on a pull request only when the head carries the new `macos-gate` label and its diff selects the job's paths filter; the label is necessary, never sufficient, so a labelled PR with no macOS path still skips the lanes. The `pull_request` trigger now also fires on `labeled`/`unlabeled`, so a `macos-gate` added after a run started begins a new run that re-evaluates the lane (removing it begins one that skips it); pull request runs are now consumers of the reuse mechanism and match source runs by their recorded tested tree, so such a re-run skips the same-tree green legs of the PR's earlier runs and costs only the label-skipped lane. A diff that touches only `crates/*/tests/**` of a lane-owned crate no longer selects the lane either — any `src/`, manifest, script, workflow or toolchain file in the same diff keeps it. The coordinator applies `macos-gate` to every PR touching `crates/terminal`, `crates/session-worker`, `crates/daemon`, `crates/test-support/src`, `crates/platform`, `runtime-packages/`, `packaging/` or `.github/` — before or right after the push, so in the normal flow the lane starts in the first run; every other PR relies on the post-merge `main` run, so a macOS-only defect in an unlabelled or tests-only PR is found on `main` after merge, never at the PR gate. Pushes to `main`, the nightly schedule and `main`/`nightly` dispatches are unchanged. ([#2599](https://github.com/zajca/pohunek/issues/2599))
