CI: the macOS jobs of `ci.yml` (`platform contracts (arm64)`, `macOS release daemon build (macos-15)`, `macOS package install and upgrade (macos-15)`, `pinned Hermes compatibility (macOS arm64, model-free)` and `SDK workspace (macOS arm64)`) now run on a pull request only when the head carries the new `macos-gate` label and its diff selects the job's paths filter; the label is necessary, never sufficient, so a labelled PR with no macOS path still skips the lanes. The `pull_request` trigger stays on `opened`/`synchronize`/`reopened` — `labeled`/`unlabeled` are excluded on purpose, since a label event would cancel and restart every PR's full CI — so the coordinator applies `macos-gate` before the PR's first push (or right after it and re-pushes; a PR that already ran unlabelled gets the lane by a re-push or a `main` tier dispatch of its head — a re-pushed PR run is a full run, because pull requests are not reuse consumers). A diff that touches only `crates/*/tests/**` of a lane-owned crate no longer selects the lane either — any `src/`, manifest, script, workflow or toolchain file in the same diff keeps it. The coordinator applies `macos-gate` to every PR touching `crates/terminal`, `crates/session-worker`, `crates/daemon`, `crates/test-support/src`, `crates/platform`, `runtime-packages/`, `packaging/` or `.github/`; every other PR relies on the post-merge `main` run, so a macOS-only defect in an unlabelled or tests-only PR is found on `main` after merge, never at the PR gate. Pushes to `main`, the nightly schedule and `main`/`nightly` dispatches are unchanged. ([#2599](https://github.com/zajca/pohunek/issues/2599))
