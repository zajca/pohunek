`pohunek service upgrade --repair` recovers a refused (`service_version_untrusted`) or missing active version directory without uninstalling: run it from the release archive of that version with `--from`. The refused entry is renamed to `.pohunek_refused-<version>-<random>` in the versions directory and kept, the release's staged copy is published in its place, `service.toml` and the worker jobs are not touched, and the daemon job is started, registered again, or restarted as a new process after the adoption preflight. A missing directory is published without the flag, an upgrade that rolls back to or resumes at a refused or missing directory gets the same repair, and `pohunek service install --repair` resumes an interrupted install the same way. `pohunek service uninstall` over an untrusted active directory and live workers now says which version to restore and how, and lists the entries repairs moved aside. The hints of `service_version_untrusted` and of `pohunek daemon start` name the command. A `refresh-path` stopped at `registering`, or rolling back from `registering` on, over such a directory is repaired in two steps: `upgrade --repair --from` restores the directory before it refuses with `service_refresh_pending`, then `refresh-path` finishes the refresh or its rollback.
