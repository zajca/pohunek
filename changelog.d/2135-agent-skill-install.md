`pohunek integration install --agent claude|codex --skill` installs the bundled Pohunek agent skill (the text `pohunek agent-skill` prints) into the agent's own skill location, opt-in per home, with an ownership marker `.pohunek-managed` beside `SKILL.md`. `integration update --skill` refreshes a marked skill of another version, `integration uninstall` removes a marked skill with the hooks (`--skill` removes only the skill), and `integration status` reports a `skill` state (`absent`, `current`, `stale`, `modified`, `foreign`, `unsafe`, `unsupported`) per home without changing the hook state. A skill Pohunek did not write, or one edited since, is never replaced or removed; it is reported, and the command exits non-zero. The runtime package declares the location in a new `[agent_skill]` table behind the runtime feature `agent-skill-v1`: the Claude package (2.1.0) uses `skills` in the config home, the Codex package (1.9.0) the shared `~/.agents/skills`, so removing one Codex profile keeps the skill (`kept_shared`) and `--all-profiles` writes it once. The packages reach a host with the release that ships this change, so `--skill` answers `integration_agent_skill_unsupported` until then. Additive wire change: `skill` on `integration.install`, `skill_only` on `integration.uninstall`, a `skill` entry in the install, status and uninstall reports, `HostCapabilities.integration_agent_skill_supported`. ([#2135](https://github.com/zajca/pohunek/issues/2135))
