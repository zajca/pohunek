A `session.new` from inside a session's process tree now records that session as the parent whatever origin markers the request carries, and markers that name another session are refused with `session_right_denied` (`reason=origin_mismatch`). `pohunek session adopt <child> <new-parent>` (`session.adopt`, advertised as `session_adopt_supported`) is the owner's way to move a session under another parent; a session gets `owner_only`, and a loop or a session inside a running `session rm --with-children` is `session_adopt_refused`. A host profile may carry a `[rights]` table: `spawn_profiles = [...]` limits the profiles a session launches (`spawn_profile_not_allowed`), and `owner_equivalent = true` gives a manager profile the rights of the owner's shell. The package methods that write profile files are owner only (`owner_only`), a session keeps at most the rights its profile had at launch, also across a daemon restart (the session record stores them from store schema 22), `plugin profile create --replace` keeps the `[rights]` table it replaces, and an owner-equivalent profile still honours its `spawn_profiles`. Manager tooling that mutates sessions it did not spawn from inside a session needs a profile with `owner_equivalent = true`. ([#2002](https://github.com/zajca/pohunek/issues/2002))
