Host agent profiles can be presets: a file with a `[preset]` table names a parent profile and a selection of its options (`[preset.options]`, optional `locked`, plus `display_name` and `audience`) and launches as the parent with that selection under its own name, so an old profile name keeps working as one choice of a shared parent. A locked preset refuses `--opt` (`agent_options_locked`). Sessions of a preset record their choices and resume with them; editing the parent's selected choice or the preset's parent needs `--accept-profile-change`, the preset's labels and choices do not. `pohunek plugin profile fold <name>... --into <parent> --dry-run` proposes such a parent and one preset per existing profile without writing anything or printing an env value. `pohunek plugin profile create` writes option profiles with `--options-file` and presets with `--preset-of <parent> [--opt OPTION=CHOICE]... [--locked]` (the new local-only `package.create_preset` method; capabilities `package_create_profile_options_supported` and `package_create_preset_supported`), and `plugin profile list` shows presets with the state `preset`. ([#2148](https://github.com/zajca/pohunek/issues/2148), [#2149](https://github.com/zajca/pohunek/issues/2149))
