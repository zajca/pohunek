`session.remove_tree` removes a session together with its descendants, deepest first: the root plus every session whose `spawned_by` chain leads to it, enumerated from a snapshot and re-read before each removal, so a child added mid-cascade is kept (with `descendant_added`) and keeps its ancestors. Every descendant goes through the normal `session.remove` safety with one exception: a live descendant is kept and never stopped (only the named root is stopped first). A dirty-worktree node is held even under `accept_unconfirmed_cleanup`, an `external` descendant is kept, a kept or refused node keeps its ancestors, and the tree is bounded at 64 sessions (more is refused with `bad_request` before anything is removed). The result counts `removed`, `kept` and `refused` and lists one row per walked node. The CLI exposes it as `pohunek session rm <id> --with-children` (one line per node with its outcome and reason, non-zero exit unless the root is removed); the socket `session.remove` keeps accepting only the bare id. The method is advertised by `HostCapabilities.session_remove_tree_supported` (clients refuse it against an older daemon before the request is sent). ([#2165](https://github.com/zajca/pohunek/issues/2165))
