`pohunek service refresh-path [--dry-run] [--json]` re-records the executable search path from your login shell, as install would record it now, and prints the directories it adds and removes (`--dry-run` stops there). Use it after installing an agent prefix later or after a Nix profile update moved the profile link; `service check` and `service upgrade` judge runtimes with the new path at once. A path that is already current changes nothing. A login shell that fails, hangs or prints junk never replaces the recorded path. New error codes: `service_search_path_refresh_failed` (the login shell gave no usable path), `service_search_path_unmanaged` (the host records no path, such as the Linux user manager), `service_refresh_blocked_by_transaction` (an install or upgrade is pending) and `service_refresh_config_schema` (`service.toml` is of another schema than this release writes; nothing is rewritten).
