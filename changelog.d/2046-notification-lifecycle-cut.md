Protocol break: protocol 5 is the only version a daemon serves, and sessions started before the upgrade must be relaunched. `notification.update`, `notification.delete`, `notification.policy.get`, `notification.policy.set` and `notification.retention.prune` are removed and answer `method_not_found`, and the error code `notification_kind_disabled` is gone. `MIN_PROTOCOL_VERSION` is 5, so a client or a session hook that announces protocol 3 or 4 is refused with `version_mismatch`; the hooks of a session launched before the upgrade carry protocol 4, so their attention reports are lost until `pohunek session` relaunches it, and the TypeScript SDK and the Rust client must be upgraded together with the daemon. The CLI keeps only `pohunek notifications list` and `watch`: `read`, `ack`, `archive`, `delete`, `policy` and `retention` are unknown-command usage errors, and `--kind` accepts only `agent_blocked` and `approval_required`. The notification inbox holds attention only. A turn end (`turn_completed`) and a turn error are no longer records: wait for them with `pohunek session wait` (`session.wait_turn`), which also returns the new `turn_error` event kind. The daemon still accepts `turn_completed`, `error` and every other kind through `notification.create` so installed hooks keep working, but stores nothing for them, and it no longer derives `session_finished`, `error` or `system` records from session state (`pohunek session list` shows the state). `notifications.jsonl` moves to format 3 on the first start: records of kinds the inbox no longer holds are hidden at once and removed by the first retention sweep, which keeps a copy as `notifications.jsonl.pre-format-3`; `policy.json` is no longer read. Resolved attention records are removed after `record_ttl_secs` (14 days). The debounce, the dedupe window, the record lifetime and the sweep interval are the optional `[notifications]` keys `attention_debounce_secs`, `attention_dedupe_window_secs`, `record_ttl_secs` and `record_sweep_interval_secs` of `service.toml`, with the previous values (5 s, 120 s) as defaults. An approval notice a terminal emits (`OSC 9`, `OSC 777 notify`, `OSC 99` starting with `Approval requested`) now creates one `approval_required` record when no OSC 7501 program-status record is held and no provider hook has spoken for the session in its current runtime generation. The notice never changes the session's activity.
