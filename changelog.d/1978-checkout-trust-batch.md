Trusted checkout arguments are decided on the checkout a session was created in and added only by the trust predicate. A resume or fork now evaluates the directory and project recorded at create (the metadata store moves to schema 16, an empty migration; a release that predates it refuses the store, and a rollback restores the `metadata.jsonl.pre-schema-15` copy) and appends the arguments only when it relaunches in that directory, so a terminal OSC 7 hint or the focus process can no longer move a session into another directory that is then trusted; a fork inherits its source's create-time directory. A session created on 0.40.x has no recorded directory and resumes and forks without the trusted arguments, with one `checkout_trust.failed` warning each time, until it is created again. A run equal to a runtime's `trusted_checkout_args` in its descriptor `args` or a host profile's `args` is dropped from a new session's command, as it already was from a resume or fork. The predicate opens each declared file without following a symbolic link in its last path component, checks the opened descriptor (a regular file of at most 4 MiB) and hashes that descriptor, so a file swapped to a symbolic link or a special file after the walk is refused instead of followed or blocked on.
