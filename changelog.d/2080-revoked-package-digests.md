A runtime package whose digest a later signed catalog revokes is now refused. The revoked digests are kept in a new `revoked-digests.json` beside `catalog-state.json`, which keeps its schema so a rollback still reads the registry. `session new`, resume, `plugin select`, enabling, profile pins and `integration install --agent hermes` (as `hermes_package_revoked`) fail with `package_revoked` and name `pohunek plugin select`; the selection is never moved on its own. Sessions already running from the digest keep running and are flagged in `session list` (a `hook` warning whose detail starts with `package_revoked`) and `plugin doctor` (finding `revoked`). A revocation file that cannot be read fails `plugin doctor`, `plugin select`, enabling, profile binds and catalog installs with the new error code `package_revocations_unreadable`, and refuses launches and resumes of catalog-authorized packages as `runtime_incompatible`; the daemon never replaces the file. A `revoked` finding of `plugin doctor` lists the sessions that still run from the digest (`running_sessions`, and a `Revoked <digest> still runs:` line in the table). `service upgrade` and `service check` judge a stopped or live session on a revoked digest `already_not_resumable` (code `package_revoked`), which does not block the upgrade.
