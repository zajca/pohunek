`session.new` accepts an optional `client_request_id` (1 to 128 bytes of `[A-Za-z0-9._:-]`) that makes the create idempotent. The daemon persists the key with a fingerprint of the request on the session's record (store schema 14); a repeated key with the same request returns the existing session with `replayed: true` and runs no hook and injects no input, the same key with another request fails with `session_request_conflict`, and a key whose create has not settled fails with `session_request_in_progress`. A rolled-back create, `session remove` and retention free the key. The fingerprint covers every parameter except the key, `cols`, `rows` and the `secret_env` values. A daemon advertises `session_new_request_id_supported` in `host.inspect`; the Rust client and the TypeScript SDK refuse to send a key to a daemon without it (`session_new_request_id_unsupported`), and protocol 3 peers refuse it with `daemon_protocol_too_old`. A release that predates schema 14 refuses the newer store; roll back with the `metadata.jsonl.pre-schema-<previous>` backup the migration takes (sessions created since are lost) or keep the newer release.
