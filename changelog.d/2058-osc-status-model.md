Agent status reads terminal OSC sequences first. `OSC 9;4` progress is parsed as typed state (0 idle, 3 working), and plain `OSC 9` notification text is no longer progress, so an approval notice does not change a session's state. OSC 7501 program-status records are authoritative only from the runtime release a manifest names in `[program_status] authority_from` (Claude 2.1.309, Codex 0.163.0, Pi 1.1.0), as probed by the session's launch; below it the worker answers no probe and the title and screen rules decide, and above it the Claude and Pi working and idle screen rules no longer decide the activity. A visible dialog over a `blocked` record reports `state_source = screen`, and a hook report outranks screen and process evidence. `session.detection` and `pohunek session detection` show the deciding source, the release gate, the held record, the probe answer and the age of the last evidence (the optional `status` object). The official Claude, Codex and Pi packages move to 1.4.0, 1.7.0 and 1.3.0 and require the new `program-status-gate-v1` runtime feature, so an older core refuses them.
