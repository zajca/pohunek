A session now records which session created it. When `session.new` or `session.fork` arrives with the request origin pair (the CLI and the Rust client send the inherited `POHUNEK_SESSION_ID` and `POHUNEK_DAEMON_ID`; the TypeScript SDK sends it when `ConnectOptions.origin` is set), the daemon stores it as the immutable `spawned_by` (`session_id`, `daemon_id`) of the new session, and `SessionInfo` reports it in `session.inspect`, `session.list` and events. `pohunek session list --spawned-by <session-id>` lists the sessions one session spawned and combines with the other list filters. The link is attribution recorded by the host from the request origin, not a security boundary: a process of the same user can omit the origin variables. The session store moves to schema 13 (a release that predates it refuses the newer store; the migration keeps a `.pre-schema-<previous>` backup), and a protocol 3 client does not see the field and is refused the filter.
